# 无障碍人工审计协作工作台

源提示词摘要：审计员记录问题、复现步骤、影响人群和严重程度，审核员判断重复或补充证据，开发人员提交修复，复测人员关闭或重新打开问题；所有核心流程可以用键盘完成，并正确管理焦点和错误提示。

## 技术栈

SolidStart、TypeScript、Park UI、Solid Router、TanStack Query、Solid Store、Modular Forms、Zod、Solid i18n primitives。

## 本地运行

```bash
npm install
npm run dev
```

## 协作账本架构（src/lib/ledger/）

多人同时开标签页处理同一批问题时，所有改动接成一份能续作的账：

- **`core.ts` 纯函数核心**：建问题、改字段、改状态、合并重复项都先追加带编号（seq）的记录，
  当前问题列表与操作时间线全部由 `replay()` 重放得出，不直接改状态。
- **并发不互相覆盖**：每条记录带 `baseSeq`（下笔时看到的编号）。提交时若同一字段已被别人
  先改，后提交的一版不生效，两版都保留并标注来源（标签页、时间、编号），可在界面上择一解决。
- **状态机**：`open → triaged → fixing → verifying → closed/reopened → fixing …`，
  越界流转直接拒绝、账本保持不变；状态更新后已确认的判定自动作废、按当前数据重算并退回待复核。
- **失败恢复**：批次合并（离线回网、重试）是事务式的——任何一条无效即回滚到最近可用结果，
  原批次完整保留在「合并失败保留的批次」里，可重试。
- **`sync.ts` 浏览器同步层**：共享账本存 localStorage，提交用 Web Locks 串行化；
  BroadcastChannel + storage 事件通知其他标签页；离线改动进每标签页独立的暂存（持久化），
  回网自动合并。
- **`migrate.ts` 旧数据升级**：本地 v1 快照自动翻译成编号记录（创建 → 沿状态机合法路径
  走到原状态 → 补录记录 → 重复合并），旧时间线原样保留，v1 数据不删除。

## 手动验证协作场景

1. **多标签页冲突**：开两个标签页，同一问题的「修复记录」各填不同内容都保存 →
   后保存的出现在「字段冲突」区，两版标来源，可择一解决。
2. **离线合并**：点「模拟离线」→ 改几条 → 另一个标签页也改 → 点「恢复在线」→
   离线批次自动合并，冲突照常判定。
3. **越界流转**：状态按钮只放行合法流转；直接注入非法记录会被账本拒绝并保留原状态。
4. **判定复核**：点「确认当前判定」后再改状态 → 判定作废重算，退回待复核。

## 可用流程

- 创建审计问题，保存复现步骤、影响人群、证据和严重程度。
- 问题按待分诊、修复中、待复测、已关闭和重新打开流转。
- 将重复问题合并到主问题，保留来源关系和操作审计。
- 开发修复与复测结果分开记录，复测失败自动重新打开。
- 支持跳过导航、可见焦点、读屏提示、`N` 快捷键聚焦新建问题、`Ctrl+Enter` 提交。
- 数据保存在 localStorage，Park UI preset 与 Ark UI 可访问交互原语参与界面实现。
